# 转为议题

用垂直切片（追踪弹）将计划拆成可独立抓取的议题。

议题追踪与分类标签词汇应已提供——若否则运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

基于对话中已有内容工作。若用户以参数传入议题引用（编号、URL 或路径），从议题追踪拉取并阅读完整正文与评论。

### 2. 探索代码库（可选）

若尚未探索，则探索以了解当前代码状态。议题标题与描述应使用项目领域词汇表，并尊重所涉区域的 ADR。

### 3. 起草垂直切片

将计划拆成**追踪弹**议题。每个议题是薄垂直切片，**端到端**贯穿**所有**集成层，而非某一层的水平切片。

切片可为 **HITL** 或 **AFK**。HITL 需要人工交互（如架构决策或设计评审）。AFK 可在无人工交互下实现并合并。可能时优先 AFK。

<vertical-slice-rules>
- 每个切片交付窄但**完整**的每层路径（schema、API、UI、测试）
- 完成的切片可独立演示或验证
- 宁可多个薄切片，不要少数厚切片
</vertical-slice-rules>

### 4. 测验用户

将拟定拆分以编号列表呈现。每个切片展示：

- **标题**：简短描述性名称
- **类型**：HITL / AFK
- **Blocked by**：须先完成哪些其他切片（若有）
- **覆盖的用户故事**：若源材料有用户故事，写明本切片覆盖哪些

询问用户：

- 粒度是否合适？（过粗 / 过细）
- 依赖关系是否正确？
- 是否应合并或进一步拆分某些切片？
- HITL / AFK 标记是否正确？

迭代直到用户认可拆分。

### 5. 发布到议题追踪

对每个已批准切片，在议题追踪发布新议题。正文使用下方模板。应用 `needs-triage` 分类标签，使议题进入常规划分流程。

按依赖顺序发布（先阻塞项），以便在「Blocked by」中引用真实议题标识符。
