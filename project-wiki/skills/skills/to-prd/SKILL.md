本技能将当前对话上下文与对代码库的理解合成为 PRD。**不要**向用户访谈——仅综合已知信息。

Issue 跟踪器与分诊标签词汇表应已提供；若未提供，请运行 `/setup-matt-pocock-skills`。

## 流程

1. 若尚未探索仓库，则探索以了解代码库当前状态。全文使用项目领域词汇表，并尊重相关 ADR。

2. 勾勒出完成实现所需构建或修改的主要模块。主动寻找可抽取、可隔离测试的深层模块（deep module）机会。

深层模块（deep module，与浅层模块 shallow module 相对）指以简单、可测试、很少变更的接口封装大量功能的模块。

与用户确认这些模块是否符合预期。与用户确认希望为哪些模块编写测试。

3. 使用下方模板撰写 PRD，然后发布到项目 issue 跟踪器。应用 `needs-triage` 分诊标签以进入正常分诊流。

<prd-template>

## 问题陈述

从用户视角描述其面临的问题。

## 方案

从用户视角描述问题的解决方案。

## 用户故事

**冗长**的编号用户故事列表。每条用户故事格式为：

1. 作为【角色】，我希望【功能】，以便【收益】

<user-story-example>
1. 作为手机银行客户，我希望查看各账户余额，以便更明智地决定消费
</user-story-example>

该列表应极其详尽，覆盖该功能的各个方面。

## 实现决策

已做出的实现决策列表，可包括：

- 将构建/修改的模块
- 将修改的模块接口
- 来自开发者的技术澄清
- 架构决策
- Schema 变更
- API 合约
- 具体交互

**不要**包含具体文件路径或代码片段——它们可能很快过时。

## 测试决策

已做出的测试决策列表，需包括：

- 何为好测试的说明（仅测外部行为，不测实现细节）
- 将测试哪些模块
- 测试的先例（即代码库中相似类型的测试）

## 不在范围内

本 PRD 明确不包含的事项说明。

## 其他说明

关于该功能的任何补充说明。

</prd-template>
