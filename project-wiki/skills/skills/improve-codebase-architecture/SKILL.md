# 改进代码库架构（Improve Codebase Architecture）

暴露架构摩擦，并提出**加深机会**——将浅层模块加深为深层模块的重构。目标是可测试性与 AI 可导航性。

## 词汇表

在每条建议中**精确**使用下列术语。语言一致性即本技能要点——不要随意换成「组件」「服务」「API」或「boundary」。完整定义见 [LANGUAGE.md](LANGUAGE.md)。

- **Module（模块）** —— 任何同时具备接口与实现的事物（函数、类、包、切片）。
- **Interface（接口）** —— 调用方使用该模块必须了解的一切：类型、不变量、错误模式、顺序、配置。不仅指类型签名。
- **Implementation（实现）** —— 其内部代码。
- **Depth（深度）** —— 接口处的杠杆：大量行为隐藏在小型接口之后。**Deep（深）** = 高杠杆。**Shallow（浅）** = 接口几乎与实现同样复杂。
- **Seam（接缝）** —— 接口所在之处；可在不就地编辑的情况下改变行为的位置。（使用此词，勿用「boundary」。）
- **Adapter（适配器）** —— 在接缝处满足接口的具体事物。
- **Leverage（杠杆）** —— 调用方从深度中获得的价值。
- **Locality（局部性）** —— 维护者从深度中获得的价值：变更、缺陷、知识集中于一处。

关键原则（完整列表见 [LANGUAGE.md](LANGUAGE.md)）：

- **删除测试**：想象删除该模块。若复杂度随之消失，它是透传。若复杂度分散到 N 个调用方，它则在创造价值。
- **接口即测试面。**
- **一个适配器 = 假想接缝。两个适配器 = 真实接缝。**

本技能受项目领域模型**启发**。领域语言为良好接缝命名；ADR 记录本技能不应重开的决策。

## 流程

### 1. 探索

先阅读项目领域词汇表及你所触及区域的任意 ADR。

然后使用 Agent 工具且 `subagent_type=Explore` 遍历代码库。不要僵化套用启发式——有机探索并记录你感受到的摩擦：

- 理解一个概念是否需要在许多小模块间反复跳转？
- 何处模块**偏浅**——接口几乎与实现同样复杂？
- 何处为可测试性而抽取纯函数，但真正缺陷藏在调用方式中（无**局部性**）？
- 何处强耦合模块在接缝处泄漏？
- 代码库哪些部分未测试，或通过当前接口难以测试？

对任何疑似浅层模块应用**删除测试**：删除它会集中复杂度，还是仅搬运复杂度？「会集中」即为你想要的信号。

### 2. 呈现候选

给出编号的加深机会列表。对每条候选：

- **Files（文件）** —— 涉及哪些文件/模块
- **Problem（问题）** —— 当前架构为何造成摩擦
- **Solution（方案）** —— 将发生何改变的通俗描述
- **Benefits（收益）** —— 用局部性与杠杆解释，并说明测试将如何改善

**对领域使用 `CONTEXT.md` 词汇，对架构使用 [LANGUAGE.md](LANGUAGE.md) 词汇。**若 `CONTEXT.md` 定义了「Order」，应讨论「Order 摄入模块」——而非「FooBarHandler」，也非「Order 服务」。

**ADR 冲突**：若某候选与既有 ADR 矛盾，仅在摩擦足够真实、值得重开 ADR 时提出。清楚标注（例如：*「与 ADR-0007 矛盾——但因……值得重开」*）。不要罗列 ADR 禁止的每一个假想重构。

**不要**在此阶段提出接口草案。询问用户：「希望深入探讨其中哪一条？」

### 3. 拷问循环

用户选定候选后，进入拷问式对话。与其一起走设计树——约束、依赖、加深后模块的形态、接缝背后是什么、哪些测试能存活。

决策成形时**同步**产生副作用：

- **将加深后的模块命名为 `CONTEXT.md` 中尚无的概念？**把该术语加入 `CONTEXT.md`——与 `/grill-with-docs` 相同纪律（见 [CONTEXT-FORMAT.md](../grill-with-docs/CONTEXT-FORMAT.md)）。若文件不存在则惰性创建。
- **在对话中收紧模糊术语？**当场更新 `CONTEXT.md`。
- **用户以关键理由拒绝候选？**提议 ADR，表述为：*「是否记录为 ADR，以免未来架构评审再次建议同一方向？」*仅在理由对未来探索者避免重复建议**确实有用**时提议——跳过短暂理由（「暂时不值得」）与自明理由。格式见 [ADR-FORMAT.md](../grill-with-docs/ADR-FORMAT.md)。
- **希望探索加深模块的替代接口？**见 [INTERFACE-DESIGN.md](INTERFACE-DESIGN.md)。
