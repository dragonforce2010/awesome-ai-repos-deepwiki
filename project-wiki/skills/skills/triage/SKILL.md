# 分类

在项目议题追踪上，通过一套小型分类角色状态机移动议题。

划分期间发往议题追踪的**每条**评论或议题**必须**以此声明开头：

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) —— 如何撰写持久的代理简报
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) —— `.out-of-scope/` 知识库如何工作

## 角色

两类**类别**角色：

- `bug` —— 有东西坏了
- `enhancement` —— 新功能或改进

五类**状态**角色：

- `needs-triage` —— 维护者需评估
- `needs-info` —— 等待报告人提供更多信息
- `ready-for-agent` —— 说明充分，可供 AFK 代理接手
- `ready-for-human` —— 需要人工实现
- `wontfix` —— 不会处理

每个已分类议题应**恰好**承载一个类别角色与一个状态角色。若状态角色冲突，先标出并询问维护者再动作。

以上为规范角色名——议题追踪中实际标签字符串可能不同。映射应已提供——若否则运行 `/setup-matt-pocock-skills`。

状态迁移：未打标签的议题通常先到 `needs-triage`；再迁到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。报告人回复后 `needs-info` 回到 `needs-triage`。维护者任意时刻可覆盖——若迁移看起来异常，先问再动。

## 调用

维护者调用 `/triage` 并用自然语言描述意图。理解请求并执行。例如：

- 「给我看看需要我关注的事项」
- 「看下 #42」
- 「把 #42 移到 ready-for-agent」
- 「现在有哪些可以给代理接的？」

## 展示需要关注的内容

查询议题追踪并呈现三个桶，**最旧的在前**：

1. **未打标签** —— 从未分类。
2. **`needs-triage`** —— 评估进行中。
3. **自上次分类备注以来报告人有活动的 `needs-info`** —— 需重新评估。

展示数量与每条议题的一行摘要。让维护者选择。

## 分类特定议题

1. **收集上下文。** 读全文（正文、评论、标签、报告人、日期）。解析既有分类备注，避免重复已解决的问题。用领域词汇探索代码，尊重 ADR。读 `.out-of-scope/*.md`，若与当前议题相似的既往拒绝则抛出。

2. **建议。** 告知维护者你的类别与状态建议及理由，外加与议题相关的简短代码库摘要。等待指示。

3. **复现（仅缺陷）。** 任何拷问前尝试复现：读报告人步骤、跟踪相关代码、运行测试或命令。报告结果——成功复现附代码路径、无法复现、或信息不足（强 `needs-info` 信号）。确认的复现能写出强得多的代理简报。

4. **拷问（如需要）。** 若议题仍需充实，跑 `/grill-with-docs` 会话。

5. **应用结果：**
   - `ready-for-agent` —— 发代理简报评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` —— 与代理简报同结构，但注明无法委托的原因（判断、外部访问、设计决策、手工测试）。
   - `needs-info` —— 发分类备注（下方模板）。
   - `wontfix`（缺陷）—— 礼貌说明后关闭。
   - `wontfix`（enhancement）—— 写入 `.out-of-scope/`，在评论中链接后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` —— 应用角色。若有部分进展可附可选评论。

## 快速状态覆盖

若维护者说「把 #42 移到 ready-for-agent」，信任其意图并直接应用角色。确认将执行的操作（角色变更、评论、关闭）再动。跳过拷问。若未经拷问 session 就移到 `ready-for-agent`，询问是否要写代理简报。

## needs-info 模板

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

把拷问中已定下的内容记入「established so far」，避免工作丢失。问题须具体可执行，不要「请提供更多信息」。

## 恢复先前会话

若议题上已有分类备注，阅读并检查报告人是否回答了悬而未决的问题，在继续前呈现更新图景。勿重复已解决的问题。
