# 转为工单（To Issues）

使用垂直切片（追踪弹）将计划拆为可独立领取的工单。

Issue 跟踪器与分诊标签词汇表应已提供；若未提供，请运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

基于对话中已有内容工作。若用户以参数传入工单引用（编号、URL 或路径），从跟踪器拉取并阅读完整正文与评论。

### 2. 探索代码库（可选）

若尚未探索代码库，则进行探索以了解当前代码状态。工单标题与描述应使用项目领域词汇表，并尊重相关 ADR。

### 3. 起草垂直切片

将计划拆为**追踪弹**工单。每个工单是穿过**所有**集成层的薄垂直切片，**不是**单层水平切片。

切片可为 `HITL` 或 `AFK`。HITL 需要人类参与，例如架构决策或设计评审。AFK 可在无人类交互下实现并合并。在可能处优先 AFK。

<vertical-slice-rules>
- 每个切片交付一条狭窄但**完整**的跨层路径（schema、API、UI、测试）
- 完成的切片本身可演示或可独立验证
- 偏好多个薄切片，而非少量厚切片
</vertical-slice-rules>

### 4. 向用户确认

将拟议拆分以编号列表呈现。对每个切片展示：

- **Title**：简短描述性名称
- **Type**：HITL / AFK
- **Blocked by**：必须先完成的其他切片（若有）
- **User stories covered**：覆盖哪些用户故事（若源材料中有）

询问用户：

- 粒度是否合适？（过粗 / 过细）
- 依赖关系是否正确？
- 是否应合并或进一步拆分某些切片？
- HITL 与 AFK 标记是否正确？

迭代直至用户批准拆分。

### 5. 发布到 issue 跟踪器

对每个已批准切片，在跟踪器发布新工单。正文使用下方模板。应用 `needs-triage` 分诊标签，使每条工单进入正常分诊流。

按依赖顺序发布（阻塞项优先），以便在「Blocked by」字段引用真实工单标识。

<issue-template>
## 父工单

对 issue 跟踪器上父工单的引用（若来源为既有工单；否则省略本节）。

## 要构建什么

对该垂直切片的简明描述。描述端到端行为，而非逐层实现细节。

## 验收标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] 标准 3

## 阻塞于

- 对阻塞工单的引用（若有）

若无阻塞项，写「无——可立即开始」。

</issue-template>

**不要**关闭或修改任何父工单。
